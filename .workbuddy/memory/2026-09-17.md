## W2 收尾：两个真缺陷修复 + 40/40 全绿（2026-09-17 晚）

**缺陷 1：`GET /api/v1/orders/mine` 未映射 → 订单页整体不可用（B000001）**
- 现象：前端 OrdersView / PersonalView 调 `/api/v1/orders/mine`，返回 `B000001 系统繁忙`。
- 根因：OrderController 只在根路径 `@GetMapping` 暴露列表，无 `/mine` 字面量映射；`/orders/mine` 落进 `@GetMapping("/{id}")`，`"mine"` 转 Long 抛 `NumberFormatException: For input string: "mine"`。
- 修复：`@GetMapping({"/mine", ""})` 双路径. 排查确认 `goods/mine`、`users/me`（`/me` 与 `/{id}` 并存）均正常返回 000000 —— Spring PathPattern 字面量优先于变量，**唯一缺陷是漏写映射**，非路由抢占。
- **沉淀规则：凡「列表/集合」类接口一律用字面量子路径，禁止依赖与 `/{id}` 的匹配优先级。**

**缺陷 2：卖家入账失败 → 订单永远无法完成（线上级）**
- 现象：`POST /orders/{id}/complete` 报「卖家入账失败」，订单卡在 FROZEN，评价连带失败。
- 根因：`t_balance_account` 建户只在充值/查余额时懒触发。**卖家从未充值 → 账户不存在 → `income` 更新 0 行**（查库确认表内只有充值过的买家账户）。真实交易中卖家首次收款必然失败。
- 修复：`BalanceService.settle` 卖家入账前、`freezeForOrder` 买家冻结前均加 `getOrCreateAccount` 兜底（后者顺带修掉买家首次下单被误报 A020002「余额不足」）。
- 资金写入前必须保证账户存在。
