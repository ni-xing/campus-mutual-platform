# 校园互助生活平台 · 项目实施计划方案

> 版本 v1.0｜2026-09-15｜依据：《高层架构设计》v0.3、《系统设计》v1.0、《UserStory》v0.3、《部署设计》v1.1、《安全设计》v1.1（均已过审归档）
> 本计划把已冻结的架构落地为"单人 6 周 + 2 周缓冲"的执行方案，所有任务编号与功能清单（F1~F18）、用户故事（US-1~US-13）一一对应，不新增不裁剪范围。

---

## 1. 目标与总体策略

### 1.1 交付目标（MVP，W1~W6）

| 目标 | 验收口径（冻结） | 对应 |
| --- | --- | --- |
| 三条主链路端到端跑通 | 二手 / 失物 / 跑腿发布→匹配→履约→完结 100% 线上化 | V2 |
| 抢单并发安全 | 并发 100 线程压测，重复接单 0 / 超接 0（附压测脚本与报告） | V3 |
| AI 可信 | 写操作后置断言覆盖率 100%，虚假确认率 0 | V4 |
| 可靠通知 | Outbox 投递成功率 ≥ 99% | V5 |
| 单机成本 | 常驻容器内存峰值 ≤ 3GB（2核4G 服务器，约 93 元/月）。**开发期零云成本：全部本地 Docker（dev 环境），服务器推迟到 W6 上线前购买**；发布时按 2.88GB 预算做一次实测校验 | V6 |
| 微服务骨架 | 网关 + Nacos + 4 业务域 + AI 全链路可演示，Sentinel 降级用例 ≥ 2 | V1 |

### 1.2 实施策略（三条铁律）

1. **骨架先行**：第 0 周先跑通 mall-swarm 裁剪版骨架（Nacos + Gateway + 两个演示服务 + Sentinel），验证启动顺序与内存预算后再仿写业务——不直接在业务代码上搭基建。
2. **每个服务"库表先行"**：按《系统设计》§4.2 的 DDL 先建库建表（7 库独立 schema），再写代码；接口按 §3.2 契约清单开发，前后端并行。
3. **每周五自检**：对照本周退出标准做一次冒烟 + 提交 tag（vX.Y.Z），不过标准不顺延任务、当周加班补齐——防止进度雪崩到 W6。

## 5. 风险与应对（实施视角）

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 本地 Docker 资源吃紧 | 开发机 ≤ 8GB 内存、风扇狂转 | observability profile 平时不开（按需启动本就是冻结设计）；常驻组合本地实测 2.88GB，8GB 机器够用；压测时关掉浏览器多余标签页 |
| 服务器迟迟未买 | W6 结束仍无 prod 环境 | 不阻塞交付：答辩/演示全部走本地 Docker（内容相同）；上线动作顺延到预算到位，自检 checklist 原样适用 |
| 服务器到货后内存超标 | 首次部署实测 > 3GB | 立即砍 Sentinel Dashboard 常驻（演示时再启）、收紧 -Xmx；仍不足升配 4核8G（+约 60 元/月） |
| 拆分粒度失控 | W1 结束仍没跑通注册链路 | 冻结拆分：先在 4 服务内合并开发，W4 前再拆回 7 服务——拆分是简历点，不是第一周的事 |
| 抢单压测翻车 | W4.6 出现重复接单 | 排查顺序：锁未生效（Redisson 配置）→ 乐观锁版本缺失 → 唯一约束缺失；三重防线逐层验证（本地即可完成压测，无需服务器） |
| LLM API 成本/限流 | 调用量异常或 429 | 调用上限 + Sentinel 熔断 + Ollama 本地兜底（系统设计 §5.2 预留） |
| 进度滑坡 | 任一周五退出标准未达 | 周末补齐；连续两周滑坡则砍 W6.3 Dashboard 至 3 个，保主链路与压测 |
| 答辩翻车 | 演示依赖外部网络 | 提前录屏兜底；Ollama 本地模型兜底 AI 环节；本地 Docker 演示不依赖公网 |

## 6. 每周固定动作（纪律）

- **每日**：代码提交 → GitHub Actions CI（构建/单测/覆盖率 ≥ 70% 门禁）；`docker stats` 巡检内存。
- **每周五**：打 tag + 周报（本周 F 编号完成情况 / 退出标准达标情况 / 下周计划）。
- **上线前（W6.6）**：跑上线自检 §7.1（9 项）+ 密钥三步扫描 checklist——服务器购买后按此执行，与本地开发完全解耦。
- **每周截图**：关键面板与演示过程存 docs/，答辩素材随做随攒，不留到 W6。

> **本地开发补充说明**：开发期成本 = 0 元（仅百炼 API 少量费用，免费额度内）；压测、Outbox 验证、AI 全链路在本地 Docker 均可完成，服务器只在 W6.6 上线时才需要。
