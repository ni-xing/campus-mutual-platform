# 04 AI 助手模块 Spec

> 上位约束见 `00-全局约定.md`。技术选型 Spring AI / LangChain4j。设计参考 OpenClaw 经验：工具调用白名单 + 防编造后置校验。

## 1. 用户故事

- 作为学生，我要用自然语言问"图书馆附近最近有没有水杯被捡到"，助手基于站内数据回答。
- 作为学生，我要问"帮我看看有什么 50 元以内的二手书"，助手直接给出商品结果。

## 2. 定位与红线（冻结）

- AI 助手是**只读查询 + 引导**角色：只能查询站内公开数据并给操作引导，不代下单、不代发布、不执行任何写操作。
- **防编造**：助手回答中涉及站内数据的部分，必须来自工具调用返回的真实结果；查不到就说查不到，禁止编造商品/物品/单子。
- 借鉴 OpenClaw 的"声明-证据校验"思路：模型回答后，校验其中引用的站内实体 ID 是否真实存在于本次工具返回中，不存在则丢弃重答。

## 3. 功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| A-01 | 会话入口 | 每用户独立会话（多轮），会话历史存 Redis（近 10 轮）+ MySQL 归档 |
| A-02 | 工具白名单 | 仅暴露 3 个只读工具：`search_goods(keyword, category, maxPrice)`、`search_lost_found(keyword, location, days)`、`search_errands(type, pickupLoc)` |
| A-03 | Function Calling | 模型根据用户意图自动选择工具；工具返回结构化 JSON 注入上下文 |
| A-04 | 防编造后置校验 | 回答中的商品/物品/单据 ID 必须出现在本轮工具结果中，否则触发一次重答，仍失败则降级为"请到对应模块查看" |
| A-05 | 兜底回答 | 超范围问题（闲聊、写操作请求）礼貌引导到对应模块页面 |
| A-06 | 敏感过滤 | 用户输入含违规词时直接拒绝回答并记录（简单词库，MVP 不引入审核服务） |

## 4. 验收标准

- AC-1：Given 站内存在"50 元以内二手书"商品，When 用户提问，Then 助手调用 `search_goods` 并在回答中列出的每个商品 ID 均来自工具返回。
- AC-2：Given 站内无匹配数据，When 用户提问，Then 助手明确回答"未找到相关…"，不出现编造条目。
- AC-3：When 用户要求"帮我下单"，Then 助手拒绝执行写操作并引导到商品详情页。
- AC-4：Given 模型回答包含不存在的商品 ID（注入模拟场景），When 后置校验执行，Then 触发重答且最终回答不含伪造 ID。
- AC-5：Given 同一用户连续多轮提问，When 第二轮追问"第一个再便宜点有没有"，Then 助手能结合上一轮上下文正确调用工具。
- AC-6：Given 助手接口响应，When 工具调用 + 生成完成，Then 端到端响应 P99 ≤ 1s 不做硬性要求，但流式输出首 token ≤ 3s（2C4G 限制下的务实目标）。

## 5. 边界与异常

- 模型/接口超时（> 10s）返回友好降级文案。
- 每用户每日问答上限 50 次（防止 token 成本失控），超限提示次日再用。
- 会话上下文截断：仅保留近 10 轮，防上下文爆炸。

## 6. 数据模型（核心表）

- `ai_session`：id, user_id, created_at, last_active_at
- `ai_message`：id, session_id, role(user/assistant/tool), content, created_at

## 7. 任务拆解

1. 建表 + 会话管理（多轮上下文）
2. 3 个只读查询工具实现（复用各模块 Service）
3. Function Calling 接入（Spring AI / LangChain4j）
4. 防编造后置校验 + 降级重答
5. 兜底回答 + 敏感词过滤 + 频次限制
6. 按 AC-1~6 写验收测试（AC-4 用模拟注入验证）
