# 05 用户与认证模块 Spec

> 上位约束见 `00-全局约定.md`。本模块是四大业务模块的前置地基：所有 AC 中"登录态"均由本模块提供。
> 口径来源：《安全设计》§2.1（密码策略/失败锁定/会话管理冻结口径）、《系统设计》§3.2.M1、UserStory US-1（AC1~AC8）。

## 1. 用户故事

- 作为学生，我要用学号 + 校园邮箱注册并登录，获得全站通用的身份。
- 作为学生，我要在个人主页看到自己的资料与信用分，作为互助信任的基础。
- 作为平台，我要在网关层统一校验每个请求的身份，内部接口对公网不可见。

## 2. 功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| U-01 | 注册 | 必填：学号(8~12位数字)、校园邮箱(域名白名单)、密码(≥8位且非纯数字)、隐私同意勾选；昵称默认"同学+学号后4位"；密码 BCrypt cost10 存储，明文不落库不落日志 |
| U-02 | 登录 | 学号或校园邮箱 + 密码；连续失败 5 次锁 15 分钟（Redis `user:login:fail:{account}` 计数）；文案防枚举（不区分账号不存在/密码错误）；成功/失败/锁定均写登录流水 |
| U-03 | JWT 签发与校验 | 本服务签发（HS256，有效期 2h，claims：userId/role/schoolCode/jti）；网关统一校验并透传用户上下文头 |
| U-04 | 互踢与登出 | 单设备策略：新登录将旧 jti 写入 Redis 黑名单（TTL=旧 Token 剩余有效期）；登出将当前 jti 写黑名单；网关校验黑名单命中即 401 |
| U-05 | 隐私同意（F18） | 注册页勾选"已阅读并同意《用户协议与隐私政策》"，未勾选不可提交（前端置灰 + 后端校验双层）；留存勾选时间与政策版本；静态政策页无需登录可达 |
| U-06 | 个人主页 | 本人主页返回完整资料 + 信用分；他人主页仅公开信息，学号一律脱敏展示（中间 4 位打星） |
| U-07 | 信用分体系 | 初始 100，区间 [0,200]；评价/履约事件通过内部接口回流加分（bizEventId 幂等，DB 唯一索引兜底）；分数单调累计无状态机 |
| U-08 | 网关统一鉴权 | 全局 JWT 过滤器 + 用户上下文透传（X-User-Id / X-User-Role / X-School-Code / X-Trace-Id）；`/internal/**` 对公网直接 404；全局限流 500 QPS、单 IP 60 QPS（触发返回 429） |
| U-09 | 链路日志 | traceId/tenantId 注入 MDC 全链路透传，结构化 JSON 日志；tenantId=schoolCode（MVP 固定 CAMPUS-MAIN） |

## 3. 验收标准

- AC-1（正常注册）：Given 合法学号与校园邮箱且已勾选隐私同意，When 提交符合强度要求的密码，Then 注册成功并自动登录。
- AC-2（邮箱不合法）：Given 非白名单域邮箱，When 提交注册，Then 提示"请使用校园邮箱"，注册不成功。
- AC-3（密码强度不足）：Given 密码为 6 位纯数字，When 提交注册，Then 提示密码要求（≥8位且非纯数字），注册不成功。
- AC-4（学号重复）：Given 学号已注册，When 再次以同学号注册，Then 提示"该学号已注册过，请直接登录"。
- AC-5（密码错误防枚举）：Given 已注册账号，When 输入错误密码登录，Then 返回"账号或密码错误"；连续失败 5 次后锁 15 分钟，锁定期内正确密码也被拒绝。
- AC-6（登出）：Given 已登录用户，When 登出，Then 当前 Token 进入黑名单，再携此 Token 访问返回 401。
- AC-7（互踢）：Given 用户在设备 A 登录后又在设备 B 登录，When 设备 A 携旧 Token 请求，Then 返回 401。
- AC-8（未勾选隐私同意）：Given 未勾选同意，When 点击注册，Then 前端按钮置灰不可提交；若绕过前端直接调接口，后端拒绝并返回参数校验错误；勾选后注册记录留存勾选时间与政策版本。
- AC-9（越权 401/404）：Given 未携带有效 JWT，When 请求业务接口，Then 返回 401；When 请求 `/internal/**`，Then 返回 404（不暴露内部接口存在性）。
- AC-10（限流）：Given 单 IP 请求超 60 QPS，When 持续请求，Then 返回 429。
- AC-11（信用回流幂等）：Given 同一 bizEventId 重复调用加分接口，Then 仅生效一次，信用分不重复变动；分数钳制在 [0,200]。
- AC-12（脱敏）：Given 任意用户主页/列表，Then 学号展示为中间 4 位打星格式（如 `2024****56`）。

## 4. 边界与异常

- 校园邮箱域名白名单可配置（配置中心），MVP 单校固定域名；新增学校只改配置。
- 密码策略按安全设计冻结口径执行：≥8 位 + 禁止纯数字，不做四类字符强制组合（以失败锁定 + 限流代偿）。
- 登录流水保留 1 年，超出后由归档策略处理；用户封禁为软封禁（status=BANNED），登录时拒绝并提示联系管理员。
- 评星到信用分增减映射（供 01/03 评价功能调用）：1星 -5 / 2星 -2 / 3星 +1 / 4星 +3 / 5星 +5；违约类事件（超时未履约）-10。
- JWT secret ≥ 256bit 强随机，仅经环境变量注入，禁止硬编码与入 Git。
- 网关透传头仅信任来自网关的流量（同信任域内网），服务端不做二次签名（接口签名已裁剪，见安全设计）。
- **身份源适配（已裁决）**：MVP 信任锚 = 校园邮箱域名白名单，不做教务系统对接（无授权接口 + 抓取学籍涉合规 + 答辩不可讲）；预留 `IdentityProvider` 适配器抽象，未来可插 CAS / 教务 / QQ / 微信身份源，注册登录主链路不变。QQ 互联登录（个人开发者可申请）放完整版 W7+，前置条件为已备案域名。
- **社交登录预留**：`t_user_identity` 绑定表本期建表（本地账号与社交账号解耦，openid 唯一约束防重复绑定），MVP 只落表结构不写绑定逻辑；微信网站扫码登录需企业资质认证，个人主体不可申请，明确不做。

## 5. 数据模型（物理表，user_db，已落地）

- `t_user_account`：id, school_code, student_no(唯一), email, password_hash, nickname, role(STUDENT/ADMIN), status(ACTIVE/BANNED), credit_score, version(乐观锁), **privacy_consent_version, privacy_consent_time**（U-05 留痕，W1 新增两列）, 审计字段, deleted
- `t_user_identity`（社交登录预留，本期建表不写逻辑）：id, user_id, idp_type(LOCAL/QQ/WECHAT/CAS), openid, unionid, bound_time, 审计字段, deleted；uk(idp_type, openid) 防重复绑定
- `t_credit_record`：id, user_id, delta, source_type(REVIEW/FULFILL/DEFAULT), score_after(快照), biz_event_id(唯一，幂等兜底), 审计字段
- `t_login_log`：id, user_id, student_no, ip, user_agent, result(SUCCESS/FAIL/LOCKED), created_time
- Redis 键约定：`user:login:fail:{account}`（失败计数）、`common:jwt:active:{userId}`（当前有效 jti）、`common:jwt:blacklist:{jti}`（黑名单）

## 6. 任务拆解

1. `t_user_account` 增加隐私同意两列 + 新建 `t_user_identity` 绑定表（DDL + gen_sql.py 同步）+ 实体/Mapper
2. 注册/登录/登出接口（BCrypt、失败锁定、JWT 签发、互踢黑名单、登录流水）
3. 个人主页接口（/users/me、/users/{id}，脱敏）+ 信用查询/内部加分接口
4. 网关接入 Nacos 注册中心 + 路由 + JWT 全局过滤器（白名单、/internal 404、限流 500/60 QPS、上下文透传）
5. common 增加 UserContextInterceptor（网关头 → UserContextHolder）+ WebFlux 版 MDC 过滤器 + logback JSON 输出
6. 按 AC-1~12 写验收测试（AC-7 互踢、AC-9 404、AC-11 幂等为必测项）
