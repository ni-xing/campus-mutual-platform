# 01 二手交易模块 Spec

> 上位约束见 `00-全局约定.md`。支付一律走模拟支付（方案 B）。

## 1. 用户故事

- 作为卖家，我要发布闲置商品（标题、描述、分类、价格、图片），让同学看到并购买。
- 作为买家，我要浏览/搜索/筛选商品，下单并用站内余额支付。
- 作为双方，我要在订单完成后互评，累计积分与信用。

## 2. 功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| S-01 | 商品发布 | 必填：标题(≤50字)、价格(>0, ≤9999)、分类、描述；图片 ≤ 9 张 |
| S-02 | 商品列表 | 分页 + 分类筛选 + 关键词搜索（标题模糊匹配）；列表走 Redis 缓存 |
| S-03 | 商品详情 | 浏览量计数（Redis 自增，定时回写 MySQL） |
| S-04 | 下单 | 校验商品在售 + 余额充足；扣余额 + 锁定商品需在同一事务 |
| S-05 | 模拟支付 | 下单即生成支付流水，点击支付成功；页面标注"模拟环境" |
| S-06 | 订单状态机 | 待支付 → 待取货(已支付) → 已完成 / 已取消；非法流转拒绝 |
| S-07 | 余额与积分 | 支付成功：买家扣余额，卖家加余额；双方各得订单金额 1% 积分（向下取整） |
| S-08 | 取消与退款 | 待支付可取消；已支付未取货可申请取消，余额原路退回 |
| S-09 | 评价 | 已完成后互评，1-5 星 + 文本(≤200字)；每人每订单仅一次 |

## 3. 验收标准

- AC-1：Given 商品在售且买家余额 ≥ 价格，When 下单并支付，Then 商品变已售、买家余额减少、卖家余额增加、生成一条支付流水。
- AC-2：Given 买家余额不足，When 下单，Then 返回"余额不足"，商品状态不变，无流水产生。
- AC-3：Given 两个买家同时下单同一在售商品，When 并发下单，Then 仅一个成功，另一个收到"商品已被下单"（数据库乐观锁或 `UPDATE ... WHERE status=在售` 行数判断）。
- AC-4：Given 订单处于"待取货"，When 调取消接口，Then 订单变已取消、买家余额退回、商品回"在售"。
- AC-5：Given 订单已"已完成"，When 再次调用支付或取消接口，Then 返回状态机错误码，状态不变。
- AC-6：Given 商品列表页首次访问，When 二次访问相同筛选条件，Then 命中 Redis 缓存（响应时间明显低于首次）。
- AC-7：Given 未勾选隐私同意的用户注册流程（全局），涉及个人信息的接口全部要求登录态。

## 4. 边界与异常

- 商品被删除时，详情页显示"已失效"，下单接口返回明确错误码。
- 价格校验：最多两位小数，负数/0/超大值拒绝。
- 图片上传限制单张 ≤ 5MB，格式 jpg/png/webp。

## 5. 数据模型（物理表，trade_db，已落地；本节逻辑名 → 物理表映射）

- `goods` → `t_goods`：id, seller_id, title, description, category, price, status(在售/已锁定/已售/已下架), view_count + 审计字段/逻辑删除
- `order` → `t_trade_order`：id, goods_id, buyer_id, seller_id, amount, status, pay_status, created_at, finished_at
- `payment` → 无独立支付表，支付/退款流水统一落 `t_balance_flow`（type 区分，biz_req_no 唯一索引幂等），订单侧以 `pay_status` 追溯支付状态
- `account` → `t_balance_account`（余额）；**积分列暂未建**，W2 实现积分时在 `t_balance_account` 或 `t_user_account` 增列（届时回填本表）
- `review` → `t_review`：id, order_id, reviewer_id, star, content（每人每订单唯一约束）
- 附：`t_goods_archive`（归档）、`t_outbox_event`（订单状态事件，通知预埋）

## 6. 任务拆解

1. 建表 + 实体/Mapper（MyBatis-Plus）
2. 商品发布/列表/详情（含 Redis 缓存与浏览量回写）
3. 下单事务 + 并发防超卖
4. 模拟支付流水 + 余额/积分变动
5. 订单状态机 + 取消退款
6. 评价功能
7. 接口联调 + 按 AC-1~7 写验收测试
