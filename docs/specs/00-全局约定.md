# 00 全局约定（Constitution）

> 本文件是所有模块 spec 的上位约束，任何模块 spec 与本文件冲突时，以本文件为准。
> 修改本文件视为"方案变更"，需冻结确认后生效。

## 1. 项目定位

校园互助生活平台，四大模块：二手交易、失物招领、跑腿拼单、AI 助手。
价值观：贴近生活、不要高大上；可学习、可落地、可答辩 > 生产级完备。

## 2. 技术栈（冻结）

| 层 | 选型 | 明确排除 |
|---|---|---|
| 存储 | MySQL + MyBatis-Plus | MongoDB |
| 缓存 | Redis | — |
| 前端 | Vue | — |
| 服务治理 | Spring Cloud（Nacos / Gateway / OpenFeign / Sentinel） | Flowable |
| RPC | Dubbo（服务间高性能调用场景） | — |
| AI | Spring AI / LangChain4j | poi-tl |

## 3. 性能目标（方案 A，冻结）

- 读接口 P99 ≤ 1s
- 并发用户 ≥ 50
- QPS ≥ 50
- 部署形态：2C4G 单机，本地 Docker 全量部署；上线前统一采购服务器

性能预算分配：Gateway 路由 + 鉴权 ≤ 50ms；热点读（商品列表、失物列表）走 Redis 缓存，缓存命中率目标 ≥ 80%。

## 4. 支付（方案 B，冻结）

- MVP 阶段为**模拟支付**：点击支付即成功，不接入真实微信/支付宝
- 配套站内**余额**与**积分**体系
- 支付流水需落库（payment 表），状态可追溯，为后续接真实支付预留状态机
- 严禁在任何文案中出现"真实支付"暗示；页面标注"模拟环境"

## 5. 合规（方案 A，冻结）

- 注册页必须包含**隐私政策同意勾选框**，未勾选不可提交
- 提供静态隐私政策页（PIPL 口径：收集目的、范围、用户权利）
- 用户密码必须加密存储（BCrypt）；手机号/学号等敏感字段展示脱敏

## 6. 通用工程约束

- 统一响应体（与后端 `Result` 实现对齐）：`{ code, msg, data, traceId, timestamp }`；成功码固定 `"000000"`；错误码 6 位分段（A=业务/B=系统/C=客户端），完整注册表见《系统设计》§3.5.1
- 所有写接口做参数校验（JSR 380）；所有需登录接口校验登录态（登录态由 05-用户与认证模块的网关 JWT 过滤器统一提供）
- 订单/跑腿单等状态流转必须用**状态机枚举**，非法流转直接拒绝
- 每个模块的 spec 变更需在文末追加变更记录
